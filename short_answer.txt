Q5. Identify the one-character error in the code and explain why that bug causes the function
to return the output you see when running on the minimal input you listed above.
You should be able to specifically account for how the error causes the result to
change from “completely correct” to “terribly wrong.”
A5. The one-character error that breaks everything is having the sumSoFar parameter include += instead of just +. When the first stack frame pops off and the function moves on to the second recursive subcall, sumSoFar builds on the previous sum. This creates an issue where the don't include case always starts off with the wrong sum. Therefore, if you make the input 1 integer, the don't include subcall will start off with a sum that includes the integer.

Q6. How much time does our visited boards tracking save us? Run the solver on the "half-done" board in the res folder and note at the bottom of the screen how many boards it said it tried. Now comment-out your code that skips already-visited boards and run the experiment again. Give the two counts and explain the results. Would you expect the percentage gap between the two counts to be same/greater/less if you re-run this experiment starting with the whole board? (try it if you dare!)
A6. Tracking visited boards saves an extremely large amount of time. The program searched 2415 boards in 7ms when keeping track of boards. On the other hand, the program searched 21364 boards in 103 ms when not keeping track. This is an extremely large time save as our solving time is more 2 orders of magnitude less. I would expect the percentage gap to be much greater if I tried the full board since the number of boards it would check is every possible status of the pieces on the board.

Q7. What edit would you need to make to change the code to apply the traditional rule that the game is only won if the last remaining marble lands in the center spot? (our version lets it land anywhere) Describe exactly where the change would be made, and what it would be.
A7. The only change we would need to do is in the success case. Instead of simply checking if there is one marble left, we would check if there is one marble left and the center square is occupied by a marble.

Q8. A leader of a political party in your hometown learns you just took CS106B.
They offer you a job working on cutting-edge software that applies algorithms to optimize
gerrymandering during the process of redistricting.

What questions might you ask about this job before making a decision? What might be the drawbacks?
Which communities would be affected by the work you're doing?

Please write your list of 3-5 questions and be sure to include ethical considerations.
A8.

1. Does “optimize gerrymandering” mean making districts fairer or helping your party win?
2. Would this work make other people’s votes matter less? Even if I support your party, everyone deserves a voice.
3. How would this affect minority communities in my hometown? Would the district lines weaken their say in elections?
4. Could the public see how the software works and raise concerns about the results?
5. Could my job focus on reducing gerrymandering? I wouldn’t want my work to help one party win unfairly.
